📖 PHẦN 2 — HƯỚNG DẪN ĐIỀN (bảng mô tả từng mục)

KhốiMục đích — điền sao cho chuẩnĐộ quan trọng
A. Định danhCho biết "công ty này là ai". Ngành nghề quyết định khuôn module (sản xuất ≠ dịch vụ ≠ thương mại).Bắt buộc
B. Tổ chứcQuyết định phân quyền + màn hình theo vai trò. Thiếu phần này → module ai cũng thấy mọi thứ.Bắt buộc
C. Quy trìnhTrái tim của module. Mô tả dòng chảy từng bước như kể chuyện cho người mới vào làm. Câu 12 (điểm đau) giúp ưu tiên đúng chỗ.Quan trọng nhất
D. Dữ liệuThành schema DB + form nhập liệu. Trạng thái vòng đời (câu 14) thành kanban/badge.Bắt buộc
E. Kết nốiĐiểm mạnh của SUPERCITADEL — module mới KHÔNG làm lại kế toán/CRM/kho mà cắm vào cái có sẵn. Câu 20 = Tiểu Tâm làm thay anh.Nên điền kỹ

⚙️ PHẦN 3 — QUY TRÌNH SAU KHI GỬI PROMPT

1
Anh gửi hồ sơ đã điền → Tiểu Tâm tổng hợp thành Bảng Mô Tả Công Ty chuẩn hóa + kiến trúc module đề xuất (schema, endpoint, màn hình, action AI).
2
Hỏi làm rõ tối đa 5 câu nếu hồ sơ có lỗ hổng quan trọng — không hỏi lan man.
3
Anh duyệt kiến trúc ("OK forge") → em forge theo chuẩn SUPERCITADEL: migration + service + routes + UI + gate Om + tutorial mini + test + audit endpoint.
4
Ship: deploy → verify thật → screenshot → push GitHub → release. Module xuất hiện trong Cửa hàng, mua/thuê bằng Om như 8 module hiện có.
💡 Mẹo điền nhanh: Nếu chưa chắc phần C-D, cứ kể tự nhiên như kể cho nhân viên mới: "Khách gọi tới thì mình…, xong rồi bên xưởng…, cuối tháng kế toán…". Tiểu Tâm tự bóc thành quy trình + dữ liệu chuẩn. Kể thật quan trọng hơn kể đẹp.
